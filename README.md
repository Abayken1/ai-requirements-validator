# Clarify AI — агент проверки требований

BCC-HUB x MNU FinTech Hackathon, команда Clarify AI (Абай Кенжетай, KIMEP University). Агент проводит статическую проверку документа с требованиями: выделяет отдельные требования, проверяет каждое и весь набор по критериям ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE Std 830-1998 (п. 4.3) и записывает отчёт на русском в PDF.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # вставь ключ в .env (см. «Ключ модели»)
python validate.py docs/requirements.md reports/report.pdf --model nvidia/nemotron-3-ultra-550b-a55b
```

Отчёт ляжет в `reports/report.pdf`. Рядом появятся `report.md` (тот же отчёт в Markdown) и `report.json` (все данные прогона).

## Ключ модели

### Как повторить сданный прогон (NVIDIA, бесплатно)

Сданный отчёт `reports/report.pdf` сделан на модели **nvidia/nemotron-3-ultra-550b-a55b** через бесплатный NVIDIA API.

1. Открой https://build.nvidia.com, войди (почта или Google), нажми **Get API Key** — ключ вида `nvapi-...`. Карта не нужна.
2. `cp .env.example .env`, в `.env` раскомментируй блок NVIDIA (4 строки `LLM_...`) и вставь ключ в `LLM_API_KEY=`.
3. Запусти:

```bash
python validate.py docs/requirements.md reports/report.pdf --model nvidia/nemotron-3-ultra-550b-a55b
```

Прогон идёт около 25 минут (модель рассуждает перед ответом; `LLM_STREAM=1` нужен, чтобы шлюз не обрывал длинные ответы). Итог сданного прогона: 37 требований, 127 нарушений (16 критичных), вердикт «Нет», 10 запросов к модели, коммит агента d6b7f75 — всё это записано в паспорте отчёта. Модель отвечает не полностью детерминированно, поэтому при повторе числа могут немного отличаться.

### Другие провайдеры

- **Google Gemini:** ключ на https://aistudio.google.com/apikey → строка `GEMINI_API_KEY=` в `.env`, модель в `GEMINI_MODEL`. В некоторых аккаунтах/регионах бесплатный тариф Gemini API недоступен (ошибка 403 «free tier is not available») — тогда используй NVIDIA.
- **OpenAI, Anthropic, любой OpenAI-совместимый API, Ollama** — примеры в `.env.example`. Агент берёт первый найденный ключ.
- Список моделей, доступных по ключу: `python validate.py --list-models`.

## Запуск

```bash
python validate.py <файл требований> <файл отчёта>
python validate.py docs/requirements.pdf reports/report.pdf
python validate.py docs/requirements.md reports/report.md --model gemini-3.5-flash
```

- Вход: `.pdf`, `.md`, `.docx`, `.txt`.
- Выход: `.pdf` или `.md`.
- Если бесплатный лимит запросов в минуту заканчивается, агент сам ждёт и повторяет запрос. Можно поставить `MAX_PARALLEL=1` в `.env`.

## Как устроен агент

```
документ → нарезчик → ревьюер требований (пачками) ┐
                    → ревьюер набора: согласованность ├─ параллельно → проверка цитат (код) → сводка (код) → итог → отчёт
                    → ревьюер набора: полнота        ┘
```

| Шаг | Файл | Что делает |
|---|---|---|
| Чтение | `agent/extract.py` | текст из PDF, DOCX, MD, TXT |
| Нарезчик | `agent/segmenter.py` | модель выделяет требования и цитаты; код проверяет каждую цитату по тексту, добавляет пропущенные пронумерованные требования (Ф-1…) и присваивает ID отчёта Т-01… |
| Ревьюер требований | `agent/reviewer.py` | каждое требование × 9 критериев ISO 29148 п. 5.2.5, в контексте всего документа |
| Ревьюеры набора | `agent/reviewer.py` | противоречия и понятность; полнота, валидация, ранжирование, модифицируемость, трассируемость (ISO 29148 п. 5.2.6, IEEE 830 п. 4.3) |
| Проверка цитат | `agent/verify.py` | каждое замечание обязано цитировать документ; если цитаты в тексте нет, замечание не учитывается и уходит в приложение отчёта |
| Сводка и решение | `agent/pipeline.py` | считает код: есть критичные дефекты — «Нет», только существенные — «С оговорками», иначе — «Да» |
| Итог | `agent/pipeline.py` | модель объясняет решение и пишет, что исправить первым |
| Отчёт | `agent/report.py`, `agent/pdf.py` | Markdown и PDF (шрифт DejaVu Sans в `fonts/`) |
| Инструкции модели | `agent/prompts.py` | все промпты |
| Критерии | `config/criteria.json` | критерии и вопросы к ним |

## Состав отчёта

1. Паспорт прогона: документ, дата, модель, версия агента (коммит git).
2. Как агент нарезал требования: ID в отчёте — ID в документе — раздел — формулировка — цитата.
3. Проверка каждого требования: матрица «требование × критерий» и дефекты с цитатой и исправлением.
4. Проверка всего набора.
5. Сводка: число требований и нарушений, критичные дефекты по типам.
6. Итог: можно ли начинать разработку и тестирование, что исправить первым.
